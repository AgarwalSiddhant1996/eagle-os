# Workspace design

## Mode and setting

Operate. Product managers review work during ordinary daylight or evening sessions. Both light and dark themes are first-class, with a system option and a user override.

## Visual language

A compact system-sans operating workspace with neutral light and charcoal dark surfaces. A restrained blue identifies actions and selected navigation. Green marks explicit recorded read/verification evidence, never completion inferred from transport. No employer branding, private assets, decorative metrics or simulated connections.

## Composition

A single 52px bar combines navigation, freshness, refresh and settings. Default tabs are Today, Work and Improvements. Navigation scrolls horizontally on narrow screens instead of widening the document. Connections, Automation and Skills live in settings. Approved domain add-ons join navigation; Remote is optional settings.

Today opens with a dense factual briefing linked to source evidence, a decision/draft column and a narrower follow-up/owner column. Cards show consequences, options, own-words responses and a source-read assertion boundary. Drafts show their actual local text and target without an external-send control. Work rows show registered owner state and actual returned thread links; details open in a story drawer.

Unconfigured workspaces use focused steps rather than a Purpose form. The connection step starts a metadata-only inventory, then presents actual available tool/repository checkboxes pre-checked. Exclusions are visible and preserved. Optional sign-in/missing entries are separate, never mixed into checked choices. Connect all selected confirms scoped read-only consent; availability does not become an implied live connection. Try a manual demo remains separate. Sources keeps access and coverage visible. Automation shows only saved/read-back schedules. Remote distinguishes unchecked, missing capability, disconnected and verified states.

## Semantic palette

Use the CSS variables for canvas, surface, raised surface, ink, muted text, line, accent, focus, verified and blocked. Dark overrides preserve the same meanings and control hierarchy. Primary-button text has its own dark-theme contrast choice.

## Interaction

All controls have keyboard focus styles and native semantics. Card responses record local choices only. Host actions state their separate scope and consent. Queued and accepted messages are not read receipts; applied patches are not verified fixes. Local revisions reject concurrent overwrite.

Setup progress checkpoints before dispatch. Live request polling must not replace unsaved forms, active typing or modal edits. Error reporting and its friction helper appear and clear together. Responsive verification covers 390px mobile and desktop in both themes, connected setup, the core tabs, settings, approved domain views and the owner story.
